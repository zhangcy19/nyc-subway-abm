# 周周期与代表权重修复

本轮只修复两个已发现的结构问题，全部离线复用真实API回复。天气时段尚未接入，人物和LLM提示不变，不通过测试结果挑参数。数据划分沿用已有六组任务；这是看过测试结果后的模型修复验证，不是新的盲测。

## 修改

1. 每个站点、票种、方法，从训练集拟合固定的七天出行活跃度。预测为“基础代表规模 × 已训练的星期活跃度 × 角色地铁概率”。星期活跃度描述潜在旅次机会，不是个人概率；可以大于1，按训练日期频率加权平均为1。目标日只查询星期，不读取当天客流。LLM仍只输出原始决策，不接收这些规模或星期系数。
2. 同票种三个角色的基础规模占比限制在10%—60%。这是防止单一虚构画像支配群体的技术约束，不是人口调查结论，也不保证真实行为异质性。它不解决LLM回复本身的随机性或跨站共享回复的问题。
3. 训练内交替拟合受约束规模与星期残差系数，共8轮。星期平滑强度候选0、1、3个平均日的伪观测；由验证集选择。原来的规模收缩和规则雨量系数仍由验证集选择，不看测试集选项。未观测到的星期默认系数1，再统一归一化。
4. 原始五类选择概率和reason不变。decisions.csv增加base_population和weekday_multiplier；effective_population现在是当天的潜在旅次机会规模，仍可与p_subway直接相乘。populations.csv保存基础规模和weekday_0…weekday_6。

这是一层可解释的周周期活动子模型，不是对所有方法提供同一个每日客流计划值。Ridge、星期均值、直接few-shot保持原样。由于ABM加入了额外的训练参数，后续比较应说明这一点，不能再将总效果完全归因于LLM组件。

## 验证

- 合成数据：角色概率不随星期变化，真实周六/周日分别为工作日的30%/10%。检查新模型能否表达这一变化。
- 单一画像可解释全部训练变化的合成数据：检查仍遵守权重占比约束。
- 六组真实数据：输出训练、验证、测试按星期的偏差、所有人群的最大角色份额、测试事件和普通日修复前后对照。
- 主实验、两次事件重复和历史示例对照均重新离线汇总；不改原始回复，不消耗新token。
- API原始证据、实际评分样本及原日期划分不变；已有测试期用于错误诊断，不能把本轮称为未见数据验证。

## 降雨时段：先讨论，不实现

传统ABM可以输入逐小时天气，也可以为角色设定上学、通勤、购物的出发时段，计算其出行与降雨重叠的暴露程度。规则随后根据暴露、步行接驳、行程必要性、公交/地铁服务等计算选择。可逐小时推进，也可只计算时段特征，最后输出日客流。

直接LLM和角色LLM也能读“凌晨03时降雨、白天无雨”等信息，但它们同样需要明确的时段输入。复杂结构化信息并非LLM独有。公平实验应给各方法等价的天气时间信息；不应仅给LLM完整时段、给规则模型一个日总雨量，再据此判断优劣。
