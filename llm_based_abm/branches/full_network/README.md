# 全站点日客流实验

本轮已完成152站、8批次、7种方法。结果见 [正式结果](staged_res/RESULTS.md)，模型输入与配置未按批次测试表现调整。原始API日志只保存在本地。

从 Normal 校准有效代表人数，在4个完整降雨事件上做留一验证。统一使用 JFK 天气；角色决策跨站共享，各站的有效代表人数和星期系数分别拟合。人数与画像份额是预测参数，不是真实人口估计。

正式站点为全部74个实验日均有24小时记录的站点，排除局部试验的256、385，共152站。此口径会偏向数据完整的站点，不能据此代表全部424站的停运情况。没有把缺失小时补成零。

## 文件与运行顺序

从本目录运行，使用 `conda activate dev`。

1. `python prepare.py`：读取项目 `data` 中原始小时数据，核查重复和票种加总，生成日表、日期划分、缺失明细和正式站点名单，保存到 `prepared/`。不调用API。已有数据无需每次重建。
2. `python verify.py`：检查完整性、训练测试隔离、群体指数计算和批量输出格式。不调用API。
3. `python run.py`：仅预检，输出请求数和token估计，不拟合、不调用API。
4. 正式执行推荐使用下文的 `staged.py` 分批入口。`python run.py --execute`是不分批的通用入口；已完成任务会直接跳过。
5. `python analyze.py`：验证结果覆盖和冻结人口，输出汇总、逐站逐日、分群体结果。不调用API。

重复执行第4步会复用已完成任务和相同请求。`--offline`禁止新API调用，可用于检查缓存。API密钥读取 `../key.txt`，不复制到输出。

`config.json`包含输出目录、并发数、预算和方案开关。本轮批准预算为1200万token；此前152站预检约需634–1022万token。预算不足会停止并保留进度。调整预算、并发数可续跑；修改数据、模型代码或科学配置必须使用新的输出目录，避免混合结果。此预检按字节估计，是范围而非实际账单。

## 数据与划分

| 任务 | 训练 | 验证 | 测试 |
|---|---|---|---|
| Normal暑期 | 7/10–7/26中符合普通天气条件的12天 | 8/1–8/7的7天 | 8/17–8/23的7天 |
| Normal非暑期 | 9/12–10/4中符合条件的15天 | 10/10–10/16的6天 | 10/23–10/29的7天 |
| Extreme | 其他3个事件的完整5天窗口作参考；人口来自对应季节Normal | 规则雨量系数只用其他3个事件选择 | 留出事件中心日及前后各2天 |

日期均为2023年。Normal排除日雨量≥10mm及达到事件阈值日期前后2天。事件中心日为7/29、8/13、9/29、10/7；前两次为短时强雨，不能统称大暴雨。精确日期见 `prepared/dates.csv`。

允许参考事件晚于目标事件；这是事后事件泛化实验。目标事件所有站点、全部5天的客流均排除在该折参考和拟合之外。Normal验证数据用于选参数，Normal测试客流从不进入提示词。Normal时期可以晚于早期事件，因此也不能将整套流程描述为当时已经可部署的实时预测。

## 方法与设置

- 星期均值、Ridge：保留原方法。Ridge在Extreme使用Normal训练加其他3个事件拟合回归系数。
- 规则ABM日汇总：原公式。
- 规则ABM时段版：将乘法放大改成绝对暴露。降雨严重度为25%全天背景＋75%画像出发时段暴露。该比例为固定假设，没有用目标事件选优；响应系数仍只在其他事件上选择。
- 角色LLM zero-shot：不提供历史群体客流；ABM外层仍用Normal数据校准人数。
- 角色LLM few-shot：Normal与Extreme使用同一种群体指数；Extreme保留4条Normal参考，再加其他3个事件。指数是“有效站点群体客流总和÷这些站点Normal训练同星期参照总和”，不是个人选择标签。缺少同星期参照时用可用Normal均值，并在提示词说明。Normal提示词只看更早训练记录。
- 直接LLM few-shot：Normal仍逐日预测；Extreme每站每事件一次输出5天。目标天气保留24小时雨量；历史天气压缩为每日统计、四个6小时雨量、峰值时刻及降雨小时。普通参考根据事件中心日选4条，全窗口共享，另有其他3个完整事件15天。

画像、10–60%组内权重约束及人口拟合算法没有修改。四组为学生票、低收入优惠票、老人/残障优惠票、普通票；老人和残障没有可分别核验的标签。`model.py`保留12个画像与Mesa概率加权汇总；`experiment.py`负责人口/星期系数和数值方法；`timing.py`负责出发时段与规则概率；`design.py`构造历史和提示词；`api.py`负责Lite调用、预算与缓存。

固定模型为 `doubao-seed-2-1-lite-260915`，temperature=0.3，关闭thinking。角色返回5种行动概率和简短理由；不是个人轨迹或真实心理记录。全市共享天气及决策，不模拟站点特有关闭、拥堵或车辆运行。

## 输出

- `staged_res/predictions.csv`：task、method、station_complex_id、date、actual、predicted，以及LLM请求hash（适用时）。
- `staged_res/decisions.csv`：逐站日、逐画像概率、基准有效人数、星期系数与人数来源。
- `staged_res/group_predictions.csv`：四个票种群体的真实和预测进站量。
- `staged_res/task_metrics.csv`、`summary.csv`：Normal及Extreme平均，同时保留5天窗口指标。
- `staged_res/station_metrics.csv`、`prediction_details.csv`：逐站、逐事件及逐日误差，方便后续作图。
- `staged_res/populations.csv`、`validation.csv`：人口参数与选参记录。
- `staged_res/api_calls.jsonl`：本地原始提示词、回复、usage；理由保留在此，通过hash关联。不要上传原始API日志或密钥。
- `staged_res/manifest.json`、`checkpoint.json`：数据代码版本和原子保存的进度。正常续跑不需手工编辑。

主得分为100×(1−WAPE)，不是分类正确率，可以为负。Normal两任务等权；Extreme四个中心日等权。站点内/站点间先汇总绝对误差，不先抵消正负误差。5天窗口另列，以免恢复日稀释中心日误差。

## 局部测试

`pilot.py rules`比较旧、新时段公式，不用API。`pilot.py llm`只跑两个旧站、非暑期人口校准接10/7这一折，并检查一个干燥验证日，硬上限100万token。`pilot_report.py`生成比较表。详细结果见 `PILOT_RESULTS.md`。

默认采用统一历史、压缩历史及事件批量输出、新时段公式。局部测试显示有收益也有损失，不是所有日期都提升；只作为工程和方案筛查。不能把同一批已观察事件上的结果包装成全新、独立的验证证据。

## 分批正式运行

本轮授权上限1200万token，配置为 `staged_config.json`，结果在 `staged_res/`。`config.json`与`staged_config.json`均指向本轮结果和1200万token上限。运行入口：

```bash
python staged.py --through-batch 1    # 首批20站
python staged.py --through-batch 2    # 前批通过后续跑第二批
python staged.py --through-batch 8    # 逐批检查，最多完成152站
python analyze.py --config staged_config.json
```

共享角色历史、人口校准和验证选参固定为完整152站口径，一次生成；逐站的直接预测按20站扩展，最后一批12站。先用训练期客流四分位及行政区安排顺序，随机种子5011；不按测试结果挑选站点。该划分只改变执行顺序，不改变模型可见数据。共享策略生成后，角色预测在更多站点的汇总只需本地计算，不再消耗API。

每批输出 `batch_XX/summary.csv`、`events.csv`、`stations.csv`、`predictions.csv`、`gate.json`。预设暂停条件：某类天气下，直接LLM平均比最佳数值方法落后超过10分，且至少60%站点也落后超过10分；或者所有LLM的最佳平均低于50分，且至少60%站点的全部LLM都低于50分。非有限值、负预测、结果覆盖错误也会停止。最差两站仅列为诊断，所有站点仍计入指标。暂停后不自动修改模型并重复测试。

这是一项控制支出的顺序实验。若提前停止，已完成站点应全部报告，不能把暂停前的样本当作完整152站结果；批次得分不用于继续调参。
